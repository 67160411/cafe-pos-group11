# WK12 — Usability Testing: brue rim lay Cafe POS

## 1. วัตถุประสงค์

เพื่อทดสอบความสามารถในการใช้งานระบบ brue rim lay Cafe POS โดยให้ผู้ทดสอบที่ไม่เคยใช้งานระบบมาก่อนทดลองทำภารกิจหลักด้วยตนเอง และสังเกตว่าระบบสามารถรองรับการทำงานของพนักงานหน้าร้านได้หรือไม่

## 2. ขอบเขตและสภาพแวดล้อม

- **ระบบ:** brue rim lay — Cafe POS
- **ประเภทการทดสอบ:** Usability Testing
- **วิธีการ:** Task-based Testing
- **ผู้ทดสอบ:** ผู้ใช้ที่ไม่เคยใช้งานระบบมาก่อน จำนวน 1 คน
- **ผู้สังเกตการณ์:** ผู้จัดทำการทดสอบ
- **อุปกรณ์:** หน้าเว็บระบบ Cafe POS
- **ขอบเขตการทดสอบ:** การเพิ่มสินค้า การแก้ไขจำนวนสินค้า การชำระเงินสด การเลือกชำระเงินด้วย QR Code การจัดการสินค้าหมด และการแสดงใบเสร็จ

## 3. วิธีดำเนินการ

ใช้ Task-based Testing โดยกำหนดภารกิจให้ผู้ทดสอบทำตามสถานการณ์จำลองการขายหน้าร้าน จำนวน 4 Tasks

ขั้นตอนการทดสอบมีดังนี้

1. ให้ผู้ทดสอบเริ่มต้นจากหน้าเว็บของระบบ
2. แจ้งโจทย์ของแต่ละ Task โดยไม่ระบุตำแหน่งปุ่มหรือบอกขั้นตอนการกด
3. ให้ผู้ทดสอบทดลองใช้งานด้วยตนเอง
4. สังเกตว่าผู้ทดสอบสามารถทำภารกิจสำเร็จหรือไม่
5. บันทึกพฤติกรรม ปัญหาที่พบ และผลลัพธ์ที่ระบบแสดง
6. สรุปประเด็นที่ควรปรับปรุงจากผลการทดสอบ

**โจทย์**

ลูกค้าต้องการ Americano จำนวน 2 แก้ว และ Latte จำนวน 1 แก้ว โดยลูกค้าจ่ายเงินสด 200 บาท ให้ดำเนินการรับออร์เดอร์และชำระเงินให้เสร็จสิ้น

**ขั้นตอนที่ผู้ทดสอบดำเนินการ**

1. กดปุ่มเพิ่ม (+) ของเมนู Americano จำนวน 2 ครั้ง
2. กดเพิ่ม (+) ของเมนู Latte จำนวน 1 ครั้ง
3. เลื่อนหน้าจอลงไปยังส่วนล่างสุดเพื่อเข้าสู่ขั้นตอนชำระเงิน
4. เลือกชำระเงินสด
5. กรอกจำนวนเงินที่รับจากลูกค้า 200 บาท
6. ยืนยันคำสั่งซื้อ
7. ตรวจสอบจำนวนเงินทอนและกดปุ่มพิมพ์ใบเสร็จ

**ผลลัพธ์ที่คาดหวัง**

- เพิ่ม Americano จำนวน 2 แก้วได้
- เพิ่ม Latte จำนวน 1 แก้วได้
- ระบบคำนวณยอดรวมได้ถูกต้อง
- สามารถเลือกชำระเงินสดและกรอกจำนวนเงินได้
- ระบบคำนวณเงินทอนได้ถูกต้อง
- สามารถแสดงใบเสร็จและกดพิมพ์ได้

**ผลการทดสอบ: PASS**

ผู้ทดสอบสามารถเพิ่ม Americano จำนวน 2 แก้วและ Latte จำนวน 1 แก้วได้สำเร็จ จากนั้นเลื่อนลงไปยังส่วนล่างสุด เลือกชำระเงินสด กรอกเงิน 200 บาท และยืนยันคำสั่งซื้อ ระบบแสดงเงินทอนจำนวน 15.00 บาท และผู้ทดสอบสามารถกดปุ่มพิมพ์ใบเสร็จได้

การคำนวณยอดเงินถูกต้อง ดังนี้

- Americano: 2 × 60 = 120 บาท
- Latte: 1 × 65 = 65 บาท
- ยอดรวม: 185 บาท
- รับเงิน: 200 บาท
- เงินทอน: 200 − 185 = 15 บาท

**ข้อสังเกต**

ผู้ทดสอบสามารถทำภารกิจได้ครบถ้วน แต่ต้องเลื่อนหน้าจอลงไปยังส่วนล่างสุดเพื่อเข้าถึงส่วนชำระเงิน จึงควรพิจารณาว่าจะทำให้ส่วนนี้เข้าถึงได้สะดวกขึ้นได้อย่างไร

### Task 2 — Happy Path: ชำระเงินด้วย QR Code

**โจทย์**

ลูกค้าต้องการ Matcha Latte จำนวน 1 แก้ว และต้องการชำระเงินด้วย QR Code ให้ดำเนินการรับออร์เดอร์และไปจนถึงขั้นตอนแสดงใบเสร็จ

**ขั้นตอนที่ผู้ทดสอบดำเนินการ**

1. เลือกเมนู Matcha Latte
2. ดำเนินการตามขั้นตอนการสั่งซื้อ
3. เลือกชำระเงินด้วย QR Code
4. กดดำเนินการชำระเงิน
5. สังเกตหน้าจอที่ระบบแสดงหลังจากกดชำระเงิน

**ผลลัพธ์ที่คาดหวัง**

- สามารถเพิ่ม Matcha Latte ลงในรายการสั่งซื้อได้
- สามารถเลือกวิธีชำระเงินด้วย QR Code ได้
- ระบบแสดงขั้นตอนการชำระเงินอย่างชัดเจน
- สามารถดำเนินการจนถึงขั้นตอนแสดงใบเสร็จได้

**ผลการทดสอบ: PASS WITH OBSERVATION**

ผู้ทดสอบสามารถทำตามขั้นตอนและเลือกชำระเงินด้วย QR Code ได้ แต่เมื่อกดชำระเงิน ระบบแสดงขั้นตอนให้พิมพ์ใบเสร็จทันที โดยไม่มีหน้าจอ QR Code แสดงขึ้นมา

ผู้ทดสอบเข้าใจว่า QR Code อาจเป็น QR Code ของร้านค้า และสามารถดำเนินการต่อไปได้ อย่างไรก็ตาม ยังไม่สามารถยืนยันได้จากการทดสอบครั้งนี้ว่าระบบมีการแสดง QR Code สำหรับรับชำระเงินจริงหรือไม่

**ข้อสังเกต**

แม้ผู้ทดสอบจะดำเนินการจนถึงขั้นตอนใบเสร็จได้ แต่ขั้นตอนการชำระเงินด้วย QR Code ยังไม่ชัดเจนจากมุมมองของผู้ใช้

หากระบบยังไม่ได้เชื่อมต่อระบบชำระเงินจริง ควรระบุให้ชัดเจนว่าเป็นการจำลองการชำระเงิน หากระบบตั้งใจรองรับการชำระเงินจริง ควรแสดง QR Code พร้อมยอดเงินที่ต้องชำระ และมีสถานะยืนยันการชำระเงินก่อนออกใบเสร็จ

### Task 3 — Error Path: สั่งเมนูที่หมดสต็อก

**โจทย์**

ลูกค้าต้องการ Iced Americano จำนวน 1 แก้ว ให้ทดลองเลือกเมนูดังกล่าวและสังเกตการตอบสนองของระบบ

**ขั้นตอนที่ผู้ทดสอบดำเนินการ**

1. ค้นหาเมนู Iced Americano
2. ทดลองกดเพิ่มสินค้า (+)
3. สังเกตสถานะเมนูและปุ่มเพิ่มสินค้า

**ผลลัพธ์ที่คาดหวัง**

- ระบบแสดงสถานะสินค้าหมด
- ผู้ใช้ไม่สามารถเพิ่มสินค้าที่หมดสต็อกลงในรายการสั่งซื้อได้
- ระบบป้องกันไม่ให้มีการสั่งซื้อสินค้าที่ไม่มีจำนวนคงเหลือ

**ผลการทดสอบ: PASS**

ผู้ทดสอบพบว่าเมนู Iced Americano แสดงสถานะว่าหมด และไม่สามารถกดปุ่มเพิ่ม (+) ได้ เนื่องจากปุ่มถูกปิดใช้งาน

ผู้ทดสอบจึงไม่สามารถเพิ่มเมนูดังกล่าวลงในรายการสั่งซื้อได้ ซึ่งเป็นไปตามพฤติกรรมที่คาดหวัง

**ข้อสังเกต**

สถานะสินค้าหมดและการปิดใช้งานปุ่มเพิ่มสินค้าช่วยให้ผู้ใช้ทราบว่าเมนูดังกล่าวไม่พร้อมจำหน่าย และช่วยป้องกันการเพิ่มสินค้าที่หมดสต็อก

จากการทดสอบครั้งนี้ไม่พบปัญหาในการใช้งานส่วนดังกล่าว

---

### Task 4 — แก้ไขจำนวนสินค้าและตรวจสอบยอดรวม

**โจทย์**

ลูกค้าต้องการ Cappuccino จำนวน 2 แก้ว แต่เปลี่ยนใจเหลือ 1 แก้ว ให้ปรับจำนวนสินค้าและตรวจสอบยอดรวมก่อนยืนยันคำสั่งซื้อ

**ขั้นตอนที่ผู้ทดสอบดำเนินการ**

1. เพิ่มสินค้า Cappuccino ลงในตะกร้า
2. ทดลองใช้ปุ่มเพิ่ม (+) และลด (-)
3. ปรับจำนวนสินค้าตามต้องการ
4. ตรวจสอบยอดรวมที่แสดงบนหน้าจอ

**ผลลัพธ์ที่คาดหวัง**

- สามารถเพิ่มและลดจำนวนสินค้าได้
- จำนวนสินค้าในตะกร้าเปลี่ยนแปลงตามการกดปุ่ม
- ยอดรวมปรับเปลี่ยนตามจำนวนสินค้า
- ผู้ใช้สามารถตรวจสอบยอดรวมก่อนยืนยันคำสั่งซื้อได้

**ผลการทดสอบ: PASS**

ผู้ทดสอบสามารถกดปุ่มเพิ่ม (+) และลด (-) เพื่อปรับจำนวนสินค้าได้ และสามารถตรวจสอบยอดรวมที่แสดงบนหน้าจอได้ โดยยอดรวมแสดงถูกต้องตามจำนวนสินค้าที่เลือก

**ข้อสังเกต**

ปุ่มเพิ่มและลดจำนวนสินค้าเข้าใจง่ายสำหรับผู้ทดสอบที่ไม่เคยใช้งานระบบมาก่อน และไม่พบปัญหาที่ทำให้ไม่สามารถปรับจำนวนสินค้าหรือตรวจสอบยอดรวมได้ในการทดสอบครั้งนี้

## 6. Usability Issues ที่พบ

ประเด็นต่อไปนี้อ้างอิงจากพฤติกรรมที่เกิดขึ้นระหว่างการทดสอบจริงและข้อสังเกตของผู้ทดสอบ โดยระดับความรุนแรงเป็นการประเมินเบื้องต้น

### Issue A — ส่วนชำระเงินต้องเลื่อนหน้าจอลง

**หลักฐานจากการทดสอบ**

ใน Task 1 ผู้ทดสอบสามารถเพิ่มสินค้าได้ แต่ต้องเลื่อนหน้าจอลงไปยังส่วนล่างสุดเพื่อเข้าถึงขั้นตอนชำระเงิน

**ผลกระทบ**

การเลื่อนหน้าจออาจเพิ่มขั้นตอนการทำงาน โดยเฉพาะเมื่อมีรายการสินค้าหลายรายการในตะกร้า

**Severity: Minor**

ผู้ทดสอบยังสามารถทำภารกิจได้สำเร็จ ปัญหานี้จึงเป็นเรื่องความสะดวกในการเข้าถึงมากกว่าการทำงานล้มเหลว

**แนวทางปรับปรุง**

- พิจารณาจัดวางยอดรวมและปุ่มชำระเงินให้อยู่ในตำแหน่งที่เข้าถึงง่าย
- อาจใช้แถบสรุปยอดและปุ่มดำเนินการที่ติดอยู่ด้านล่างของหน้าจอ
- ทดสอบซ้ำกับผู้ใช้เพื่อประเมินว่าการปรับตำแหน่งช่วยลดขั้นตอนได้จริงหรือไม่

### Issue B — ขั้นตอนชำระเงินด้วย QR Code ไม่ชัดเจน

**หลักฐานจากการทดสอบ**

ใน Task 2 ผู้ทดสอบเลือกชำระเงินด้วย QR Code ได้ แต่หลังจากกดชำระเงิน ระบบแสดงขั้นตอนพิมพ์ใบเสร็จทันที โดยไม่ปรากฏหน้าจอ QR Code

ผู้ทดสอบเข้าใจว่าอาจเป็น QR Code ของร้านค้า แต่ยังไม่สามารถยืนยันได้จากหน้าจอที่พบ

**ผลกระทบ**

ผู้ใช้หรือพนักงานอาจไม่แน่ใจว่าต้องให้ลูกค้าสแกน QR Code จากที่ใด และการชำระเงินได้รับการยืนยันแล้วหรือไม่

**Severity: Major หากระบบตั้งใจรองรับการชำระเงินจริง**

หากเป็นเพียงระบบจำลองการชำระเงิน ความรุนแรงอาจลดลง แต่ควรสื่อสารสถานะให้ชัดเจน

**แนวทางปรับปรุง**

- หากรองรับการชำระเงินจริง ให้แสดง QR Code และยอดเงินที่ต้องชำระ
- เพิ่มสถานะการชำระเงินที่ตรวจสอบได้ก่อนออกใบเสร็จ
- หากยังเป็นเพียงการจำลอง ให้แสดงข้อความชัดเจนว่าระบบไม่ได้รับชำระเงินจริง
- ทดสอบซ้ำเพื่อให้แน่ใจว่าผู้ใช้เข้าใจขั้นตอนการชำระเงิน

## 7. การแก้ไขและการทดสอบซ้ำ (Fixes and Retesting)

จากผลการทดสอบครั้งนี้ ยังไม่ได้ดำเนินการแก้ไข source code จึงยังไม่มีผลการทดสอบซ้ำหลังแก้ไข

แนวทางดำเนินการต่อ ได้แก่

1. พิจารณาปรับตำแหน่งส่วนชำระเงินเพื่อให้เข้าถึงได้ง่ายขึ้น
2. ตรวจสอบการทำงานของ QR Code ว่าเป็นการจำลองหรือรองรับการชำระเงินจริง
3. หากแก้ไขหน้าจอหรือขั้นตอนชำระเงิน ให้ทดสอบ Task 1 และ Task 2 ซ้ำ
4. หากแก้ไขหน้าตะกร้าสินค้า ให้ทดสอบ Task 4 ซ้ำ
5. บันทึกผลก่อนและหลังการแก้ไขโดยอ้างอิงจากการทดลองใช้งานจริง

## 8. สรุปผล (Conclusion)

จากการทดสอบระบบ brue rim lay Cafe POS โดยผู้ทดสอบที่ไม่เคยใช้งานมาก่อนจำนวน 1 คน พบว่าผู้ทดสอบสามารถทำภารกิจทั้ง 4 รายการได้สำเร็จ

ระบบสามารถรองรับการเพิ่มสินค้า การปรับจำนวนสินค้า การคำนวณเงินทอน และการป้องกันการเพิ่มสินค้าที่หมดสต็อกได้ตามที่คาดหวัง

อย่างไรก็ตาม พบประเด็นที่ควรปรับปรุง 2 ประเด็นหลัก ได้แก่

1. การเข้าถึงส่วนชำระเงินที่ต้องเลื่อนหน้าจอลงไปยังส่วนล่างสุด
2. ความชัดเจนของขั้นตอนชำระเงินด้วย QR Code ซึ่งหลังจากกดชำระเงิน ระบบแสดงขั้นตอนพิมพ์ใบเสร็จทันทีโดยไม่มีหน้าจอ QR Code

ดังนั้น ระบบสามารถใช้งานภารกิจพื้นฐานที่ทดสอบได้ แต่ควรปรับปรุงและตรวจสอบขั้นตอนชำระเงินด้วย QR Code เพิ่มเติม เพื่อให้ผู้ใช้เข้าใจสถานะการชำระเงินและมั่นใจในการใช้งานมากขึ้น

**ข้อจำกัดของการทดสอบ:** ผลลัพธ์นี้มาจากผู้ทดสอบ 1 คน และไม่มีการบันทึกเวลาใช้งานหรือคำพูดแบบคำต่อคำ จึงควรทดสอบเพิ่มเติมกับผู้ใช้หลายคนเพื่อให้ได้ข้อสรุปที่ครอบคลุมยิ่งขึ้น
