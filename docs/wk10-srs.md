# Software Requirements Specification (SRS)

## ระบบจัดการร้านกาแฟ

# 1. Introduction

## 1.1 Purpose

เอกสารนี้รวบรวมความต้องการของระบบร้านกาแฟจาก Requirements, Use Case Diagram, ER Diagram และแบบออกแบบหน้าจอ Input–Output เพื่อใช้เป็นแนวทางในการพัฒนาและทดสอบระบบ

## 1.2 Scope

ระบบรองรับการสร้างคำสั่งซื้อ คำนวณราคา รับชำระเงิน ออกใบเสร็จ จัดการเมนู ตรวจสอบสต็อก และดูรายงานยอดขาย โดยใช้การจำลองการชำระเงิน ไม่เชื่อมต่อผู้ให้บริการชำระเงินจริง

## 1.3 References

- `docs/wk03-requirements.md`
- `docs/images/use-case-diagram.png`
- `docs/wk07-er-diagram.png`
- `docs/POS/` (ออกแบบหน้าจอ Input–Output)

# 2. Overall Description

## 2.1 User Classes

| ผู้ใช้งาน           | หน้าที่                                   |
| ------------------- | ----------------------------------------- |
| พนักงาน             | สร้างคำสั่งซื้อ รับชำระเงิน และออกใบเสร็จ |
| บาริสต้า            | รับและตรวจสอบรายการออเดอร์                |
| เจ้าของร้าน/ผู้ดูแล | จัดการเมนู ตรวจสอบสต็อก และดูรายงานยอดขาย |

## 2.2 Constraints and Assumptions

- ใช้ Node.js, Express และ MySQL
- ใช้ฐานข้อมูลเดียวเพื่อจำลองร้านกาแฟหลายสาขา
- การชำระเงินเป็นการจำลองภายในโครงงาน

# 3. Specific Requirements

## 3.1 Functional Requirements (FR)

| รหัส  | ข้อกำหนด                                                                       | Use Case        |
| ----- | ------------------------------------------------------------------------------ | --------------- |
| FR-01 | ระบบจะให้พนักงานเลือกเมนูและจำนวนเพื่อสร้างคำสั่งซื้อ                          | สร้างคำสั่งซื้อ |
| FR-02 | ระบบคำนวณราคารวมจากราคาและจำนวนสินค้าอย่างถูกต้อง                              | คำนวณราคารวม    |
| FR-03 | ระบบจะบันทึกวิธีและสถานะการชำระเงิน                                            | รับชำระเงิน     |
| FR-04 | ระบบต้องสร้างใบเสร็จที่แสดงวันที่ พนักงาน เลขที่ใบเสร็จ รายการสินค้า และยอดรวม | พิมพ์ใบเสร็จ    |
| FR-05 | ระบบต้องแสดงรายการคำสั่งซื้อให้บาริสต้าตรวจสอบ                                 | รับออเดอร์      |
| FR-06 | ผู้มีสิทธิ์ต้องสามารถเพิ่ม แก้ไข และลบเมนูได้                                  | จัดการเมนู      |
| FR-07 | ระบบจะแสดงข้อมูลสต็อกและรองรับการบันทึกการเปลี่ยนแปลงสต็อก                     | ตรวจสอบสต็อก    |
| FR-08 | ระบบต้องแสดงรายงานยอดขายตามช่วงเวลาที่เลือก                                    | ดูรายงานยอดขาย  |

## 3.2 Non-Functional Requirements (NFR)

| รหัส   | ประเภท         | ข้อกำหนด                                                                       |
| ------ | -------------- | ------------------------------------------------------------------------------ |
| NFR-01 | Performance    | ระบบควรแสดงผลการสร้างคำสั่งซื้อภายใน 2 วินาที                                  |
| NFR-02 | Usability      | พนักงานใหม่ควรสร้างคำสั่งซื้อได้ภายใน 5 นาทีหลังได้รับคำแนะนำ                  |
| NFR-03 | Security       | ระบบต้องจัดเก็บรหัสผ่านด้วยแฮช เช่น bcrypt ไม่เก็บเป็นข้อความปกติ              |
| NFR-04 | Security       | ระบบต้องตรวจสอบสิทธิ์ก่อนอนุญาตให้เข้าถึงหรือแก้ไขข้อมูลที่สำคัญ               |
| NFR-05 | Data Integrity | ระบบต้องคำนวณราคาจากข้อมูลฝั่งเซิร์ฟเวอร์ ไม่เชื่อถือราคาที่ส่งจากผู้ใช้โดยตรง |
| NFR-06 | Performance    | รายงานยอดขายควรแสดงผลภายใน 5 วินาทีสำหรับข้อมูลทดสอบของโครงงาน                 |

# 4. External Interface Requirements

ระบบเป็นเว็บแอปพลิเคชัน ใช้ HTML, CSS และ JavaScript สำหรับหน้าจอ และใช้ Node.js, Express และ MySQL สำหรับการประมวลผลและจัดเก็บข้อมูล

แบบออกแบบหน้าจอใน `docs/POS/` ประกอบด้วย

1. New Order: เลือกเมนู ระบุจำนวน ดูราคาต่อหน่วย ยอดรวม และเลือกวิธีชำระเงิน
2. Receipt: แสดงวันที่ พนักงาน เลขที่ใบเสร็จ รายการสินค้า ราคา และวิธีชำระเงิน
3. Sales Report: แสดงสาขา ช่วงเวลา จำนวนที่ขาย ราคาต่อหน่วย และยอดขายรวม

การเลือก QR Code ในหน้าจอเป็นเพียงตัวเลือกตามการออกแบบ ไม่ได้หมายความว่าระบบเชื่อมต่อเพื่อรับชำระเงินจริง

# 5. Data Requirements

อ้างอิง ER Diagram `docs/wk07-er-diagram.png` ซึ่งประกอบด้วยตารางหลักดังนี้

| Entity           | หน้าที่                        |
| ---------------- | ------------------------------ |
| `branch`         | เก็บข้อมูลสาขา                 |
| `employee`       | เก็บข้อมูลพนักงาน              |
| `orders`         | เก็บข้อมูลคำสั่งซื้อ           |
| `order_item`     | เก็บรายการสินค้าในคำสั่งซื้อ   |
| `menu_item`      | เก็บข้อมูลเมนู ราคา และสต็อก   |
| `category`       | เก็บหมวดหมู่เมนู               |
| `stock_movement` | เก็บประวัติการเปลี่ยนแปลงสต็อก |

ตารางเชื่อมโยงกันด้วย Primary Key และ Foreign Key เช่น คำสั่งซื้อเชื่อมกับพนักงานและสาขา ส่วนรายการคำสั่งซื้อเชื่อมกับเมนู ทั้งนี้ ER Diagram ปัจจุบันแสดงสต็อกระดับเมนู แต่ยังไม่แสดงตารางวัตถุดิบและสูตรส่วนผสมโดยตรง

# 6. Input–Output Requirements

| หน้าจอ       | Input                          | Output                                              |
| ------------ | ------------------------------ | --------------------------------------------------- |
| New Order    | เมนู จำนวน และวิธีชำระเงิน     | รายการสินค้า ราคาต่อจำนวนชิ้น และยอดรวม             |
| Receipt      | ข้อมูลคำสั่งซื้อและการชำระเงิน | วันที่ พนักงาน เลขที่ใบเสร็จ รายการสินค้า และยอดรวม |
| Sales Report | สาขาและช่วงเวลาที่ต้องการดู    | รายการเมนู จำนวนที่ขาย ราคาต่อหน่วย และยอดขายรวม    |

# 7. Acceptance Criteria

1. สร้างคำสั่งซื้อและคำนวณยอดรวมได้ถูกต้อง
2. บันทึกการชำระเงินและแสดงใบเสร็จได้ตามข้อมูลคำสั่งซื้อ
3. แสดงรายการออเดอร์สำหรับบาริสต้าได้ตามความสามารถของระบบ
4. ผู้มีสิทธิ์สามารถจัดการเมนูและตรวจสอบข้อมูลสต็อกได้
5. แสดงรายงานยอดขายตามช่วงเวลาที่ระบบรองรับได้ถูกต้อง
6. ระบบตรวจสอบสิทธิ์และป้องกันการแก้ไขข้อมูลโดยผู้ไม่มีสิทธิ์

# 8. Conclusion

เอกสาร SRS นี้รวบรวมความต้องการของระบบร้านกาแฟจาก Requirements, Use Case Diagram, ER Diagram และแบบออกแบบหน้าจอ Input–Output เพื่อใช้เป็นแนวทางในการพัฒนาและทดสอบระบบให้ตรงตามความต้องการของกลุ่ม
